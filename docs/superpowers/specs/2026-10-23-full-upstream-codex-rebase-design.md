## Claude review dispositions and concrete lifecycle design

- F1 accepted. Linux uses a small dedicated Python supervisor, launched as a new session leader with an inherited control pipe. The monitor holds the write end; normal close, a crash, SIGTERM or SIGKILL of the monitor closes it in the kernel. The supervisor alone holds the read end; the Codex child does not inherit it. Codex inherits supervisor stdio directly, preserving JSONL without a proxy. The supervisor remains the session/process-group leader until cleanup finishes, so its group identity cannot be reused while signaled. It installs a caught SIGTERM handler (reset to default across the child exec), becomes a Linux subreaper, and shuts down only its own group. After a bounded TERM grace period, use pidfds for surviving group members, excluding the supervisor, then reap children before exiting. No threaded Python preexec_fn is used. Tests cover graceful quit, app-server crash, spawn/handshake failure, TTL restart, monitor SIGTERM and SIGKILL, a blocked stdin writer, stubborn descendants, and survival of an unrelated sentinel process. Require modern Linux pidfd support or fail child startup visibly before launching Codex; document that requirement. Windows Job cleanup remains a separate native backend.
- F2 accepted. The rebased committed baseline must pass the full Windows suite independently. Then adapt the privately preserved shutdown overlay as uncommitted changes, retain its regression tests, and run the full suite again with separate counts. Linux must provide the same observable graceful-EOF, bounded fallback, no-overlap and descendant-reaping behavior, even when the platform implementation differs. Keep both verification artifacts.
- F3 accepted. Linux tests explicitly cover Codex-named single-instance lock, XDG autostart filename/content, tray/application identity, settings/log paths, default/custom homes and source launcher from an unrelated directory. A signed-out pair of Claude/Codex processes may be used only with isolated synthetic homes; no live credentials or settings are touched.
- F4 accepted. Attempt an actual GTK/WebKit popup and tray startup under Xvfb/D-Bus in a disposable container. Document Linux as experimental if desktop integration cannot be exercised, and precisely report X11 virtual-display versus real KDE/GNOME/Wayland coverage. Never turn headless imports into a desktop-validation claim.
- F5 accepted. A regression supplies complete synthetic Codex data including credits metadata and proves no active billing or prepaid UI reaches the popup. API/boundary tests keep credits dropped. Public configuration and README explicitly omit or label dormant extra-usage/currency settings, and no trust-store HTTP dependency remains solely for removed Anthropic networking.
- F6 accepted as a validation gap; no new installer behavior is needed. Both platforms invoke only fixed `codex update` with platform-appropriate subprocess options, after provider operation serialization and confirmed child cleanup. Test success, unchanged version, nonzero exit, timeout, and child-exit refusal on Linux as well as Windows. Never elevate or fall back to another installer command. An installation whose CLI does not support this updater is documented to fail safely and retry at the configured interval.
- F7 accepted with a Codex-specific cadence constraint. Retain upstream Linux idle/lock mechanisms and document their desktop availability. Tests cover an uncovered visible popup, locked state, unavailable lock/idle detection and resumption. Unknown lock state must not emit sensitive account notifications; represent it explicitly if the upstream boolean fallback cannot express that safely. Cap the away cadence to the Codex healthy-child lifetime (600 seconds), preserving reset scheduling and auth-revision observation; expire/recycle only between logical provider operations. Document this justified difference from upstream's 900-second default.

These are implementation decisions within the owner's approved full-rebase and Linux scope, not new product requirements or publication authorization.

### Final review dispositions

The second and final Claude review accepted the resolution of the first review's F2-F7. Its remaining F1 is accepted: Linux cleanup enumerates the supervisor's live descendant tree through /proc as well as its own group, including adopted children and processes that called setsid/setpgid. Keep identities as PID plus start time, open pidfds, recheck the live identity/ancestry before signaling, and repeat until all owned descendants have exited and been reaped. Add a detached-descendant regression and unrelated-process sentinel. Avoid numeric-PID signals for the force phase.

Second-review F2 is a documented residual failure mode: an external SIGKILL/OOM of the supervisor itself cannot provide the same unconditional containment as a Windows kill-on-close Job. Test monitor death and supervisor SIGTERM, document the remaining supervisor-failure limit, and do not claim identical kernel guarantees. F3 is accepted: install signal handlers and probe required kernel capabilities before child spawn; fixed supervisor startup failure markers go only to stderr with a nonzero exit, never JSONL stdout, and are covered by tests. F4 is rejected as a product blocker: private snapshot files and the isolated branch are allowed shared repository metadata; unchanged means the original branch tip, index and worktree content remain untouched. Verify those explicitly.
